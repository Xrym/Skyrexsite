# Skyrex Computers — Карта проекта и инструкции для ИИ (GEMINI.md)

Документ содержит описание архитектуры проекта, назначение всех файлов, правила взаимодействия компонентов и регламент развертывания.

---

## 1. Обзор проекта
**Skyrex Computers** (`https://skyrex.pro/`) — интерактивная веб-платформа с ИИ-консультантом для автоматического подбора сбалансированных конфигураций ПК под любой бюджет с учетом реальных цен, совместимости и прямых ссылок на маркетплейсы.

---

## 2. Структура файлов и назначение

### Frontend (Клиентская часть)
* `index.html` — Главная страница приложения. Содержит Hero-секцию, разметку чата с ботом, контейнер для интерактивного визуализатора (`#skyrex-pc-visualizer`), секцию возможностей и модальные окна (авторизация, профиль). **При изменении CSS/JS обязательно обновлять query-параметр версии (`?v=...`)!**
* `style.css` — Основная таблица стилей. Включает неоновые темы, сетку рабочего пространства `.hero-workspace-grid`, интерактивную подсветку визуализатора, карточки деталей, стили всплывающих подсказок ввода `.chat-autocomplete` и адаптивную верстку для мобильных устройств.
* `rig_visualizer.js` — Интерактивный визуализатор сборки (`SkyrexRig`):
  - Рендеринг SVG-чертежа корпуса ПК с подсветкой контуров компонентов при наведении.
  - Список карточек компонентов с магазинами (Авито, ОнлайнТрейд, WB, DNS) и прямой ссылкой.
  - Метод `updateFromAiResponse(text)` — разбор текста ответа ИИ в реальном времени, извлечение цен, категорий, тегов и ссылок.
  - Функция `escapeHtml()` — обязательная санитизация названий деталей от спецсимволов и некорректных тегов.
* `chat_bot.js` — Логика ИИ-чата:
  - Обработка ввода пользователя, отправка запросов на бэкенд (`/api/chat/stream`).
  - Потоковый прием ответов по Server-Sent Events (SSE) через `ReadableStreamDefaultReader`.
  - Механизм подсказок при вводе (`chat-autocomplete`) по словарю `AUTOCOMPLETE_ITEMS` с навигацией клавиатурой (Tab, стрелки, Enter).
  - Форматирование Markdown в HTML (`parseBotContent`).
  - Синхронизация с визуализатором (`SkyrexRig.updateFromAiResponse`).
* `auth.js` — Управление сессиями, вход, регистрация, хранение JWT-токенов в `localStorage`.
* `app.js` — Инициализация общих скриптов сайта, навигация, плавная прокрутка, анимации.

### Backend (Серверная часть)
* `server.py` — Основной веб-сервер на `aiohttp` / `gunicorn` (порт 5000):
  - API эндпоинты чата (`/api/chat/stream`, `/api/chat`).
  - Системный промпт ИИ-эксперта SkyRex (свод базовых стандартов зашит в коде `db/prompt_defaults.py`: баланс CPU/GPU, совместимость сокетов, 8 обязательных позиций, строгий лимит бюджета, градации БП/кулеров, корпуса XASTRA, ссылки на Авито).
  - Интеграция с Google Gemini API и автоматический фоллбек на OpenRouter API при высокой нагрузке или исчерпании квот.
  - Авторизация, управление сессиями, раздача статических файлов.
* `db/prompt_defaults.py` — Модуль хранения эталонного системного промпта (`assistant_system`) со всеми правилами эксперта Skyrex.
* `requirements.txt` — Python-зависимости (aiohttp, google-generativeai, openai, requests, paramiko и др.).
* `nginx.skyrex.conf` — Конфигурация Nginx для продакшена (проксирование на 127.0.0.1:5000, SSL Let's Encrypt, сжатие, заголовки безопасности).
* `skyrex.service` — Unit-файл Systemd для управления сервисом приложения на сервере.

### Базы данных и парсеры
* `catalog.db` — База данных SQLite с актуальными комплектующими, ценами, магазинами и категориями.
  - Таблица `ai_rules` предназначена **исключительно для коротких оперативных правил от администратора**, добавляемых через Telegram-бота (базовые правила зашиты в коде).
* `users.db` — База данных пользователей и токенов авторизации.
* `run_scraper.py` / `scraper_menu.py` — Скрипты парсинга актуальных цен с маркетплейсов (Wildberries, ОнлайнТрейд, DNS, Авито).
* `run_tg_bot.py` / `tg_admin_bot.py` — Telegram-бот администратора для мониторинга, уведомлений и оперативного управления короткими правилами ИИ (`skyrex-tg-bot.service`).

### Деплой и инфраструктура
* `deploy.py` — Главный автоматический скрипт деплоя. Выполняет:
  1. Проверку локальных изменений Git и создание коммита.
  2. Отправку в удаленный репозиторий (`git push origin main`).
  3. Подключение по SSH к серверу `87.120.84.33`.
  4. Запуск `update.sh` (git pull, обновление зависимостей, перезапуск `skyrex.service`).
  5. Проверку доступности сайта по HTTPS `https://skyrex.pro/`.

## 3. Критические правила и архитектурные контракты

1. **Кэш-бастинг (Cache-busting)**:
   При любых изменениях в `style.css`, `rig_visualizer.js`, `chat_bot.js` или `auth.js` необходимо **обязательно инкрементировать версию `?v=...`** во всех тегах `<link>` и `<script>` в [index.html](file:///c:/code/skyrex-main/index.html).

2. **Flexbox-структура визуализатора**:
   - Контейнер карточки `.pc-rig-card` строго: `display: flex !important; flex-direction: column !important; width: 100%;`.
   - Рабочая область `.pc-rig-stage-wrapper`: `display: flex !important; flex-direction: row !important;` (на мобильных устройствах `@media (max-width: 768px)` переключается в `column !important`).
   - Схема корпуса `.pc-chassis-stage`: фиксированная ширина `flex: 0 0 280px !important;`.
   - Список деталей `.pc-components-list`: `flex: 1 1 auto !important; min-width: 260px !important;`.
   - Футер визуализатора `.pc-rig-footer`: `width: 100% !important; flex-shrink: 0 !important;` — всегда во всю ширину внизу.

3. **Безопасность разметки визуализатора**:
   Любые данные из ответа ИИ перед генерацией HTML-карточек в [rig_visualizer.js](file:///c:/code/skyrex-main/rig_visualizer.js) обязаны проходить через `this.escapeHtml()`, чтобы кавычки или спецсимволы не нарушали структуру DOM.

4. **Парсинг цен в визуализаторе**:
   Парсер [rig_visualizer.js](file:///c:/code/skyrex-main/rig_visualizer.js) извлекает строки только формата `1. Категория: Название — Цена руб.` Номера моделей (например, `5600.`) не должны разбивать строки списка.

5. **Выкатка изменений**:
   Всегда использовать `python deploy.py "<Commit message>"`.

6. **Динамическая база данных и запрет жестко заданных цифр (Dynamic Market & Pricing)**:
   - База данных `catalog.db` является **строго динамической** и непрерывно актуализируется парсерами цен с маркетплейсов (Wildberries, ОнлайнТрейд, DNS, Авито).
   - Рыночные цены, наличие позиций и курсы валют постоянно меняются, поэтому **категорически запрещено жестко зашивать конкретные цифры** (фиксированные цены комплектующих, жесткие пороги «минимального прайса», фиксированные стоимости сборок) в коде фронтенда, бэкенда, кнопках подсказок или системных правилах.
   - Любые статичные цифры несовместимы с динамическим рынком и приводят к рассинхронизации. Все расчеты, подборы и проверки должны опираться исключительно на актуальные динамические данные из базы `catalog.db` или формироваться ИИ-консультантом в реальном времени под текущие рыночные реалии.

7. **Обязательная авторизация для общения с ИИ-консультантом (Mandatory Chat Authentication)**:
   - Доступ к отправке запросов в ИИ-чат (`/api/chat`) и подбору сборок разрешен **строго авторизованным пользователям**.
   - Бэкенд (`server.py`) валидирует токен сессии через заголовок `Authorization: Bearer <token>` и `get_user_by_token(token)`, возвращая HTTP 401 при отсутствии или недействительности токена.
   - Фронтенд (`chat_bot.js`) перехватывает ввод неавторизованного пользователя до отправки, предлагает войти или зарегистрироваться и сразу открывает окно авторизации `SkyrexAuth.openAuthModal()`.

8. **Откат сообщений при ошибках и Gemini-UX чата (Chat UX & Error Rollback)**:
   - При любых ошибках генерации ответа ИИ (сбой сети, 401, 429, 500, ошибка потока) неотвеченное сообщение пользователя удаляется из DOM и истории, а его исходный текст возвращается обратно в поле ввода `chatInput` с автоматическим фокусом и установкой курсора в конец строки для быстрого повтора по клавише Enter.
   - В чате поддерживаются современные удобства: вызов истории отправленных запросов по стрелкам `↑` / `↓` в пустом поле ввода, кнопка редактирования запроса ✏️ на сообщениях пользователя, кнопка повторной генерации 🔄 на ответах ИИ и система всплывающих тост-уведомлений.
